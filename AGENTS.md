# Repository conventions

- Group system configurations under `hosts/<platform>/`; keep per-user Home Manager configurations under `home/`.
- Keep shared defaults in `modules/<platform>/base.nix`. Import optional modules explicitly from host or home configurations; do not recursively auto-import modules.
- Do not add a profiles layer unless shared machine roles make it necessary.
- Preserve pinned inputs and existing `stateVersion` values during layout refactors.
- Collapse single-child attribute nesting into dotted paths. Keep attribute sets where they group multiple settings.
- Use blank lines between logical sections and sibling blocks; keep closely related scalar settings together.
- Omit settings that merely repeat defaults unless they document an important hardware or safety requirement; check the pinned module defaults before removing them.
- Keep services and integrations minimal; add optional daemons and hardware support only when needed for the current setup.
- The Macs use Determinate Nix. Keep `nix.enable = false`, but manage `/etc/nix/registry.json` through `environment.etc`, using the `nix.registry` declarations. Do not let nix-darwin replace Determinate's daemon or `nix.conf`.

# Verification

- Use the official `nixfmt` formatter via `nix fmt` (`nixfmt-tree` handles the repository). Check formatting with `nix fmt -- --fail-on-change`.
- Evaluate Darwin outputs with `nix eval --raw .#darwinConfigurations.<host>.system.drvPath`.
- Build Home Manager without activation or replacing `result`: `nix build --no-link --no-write-lock-file '.#homeConfigurations."oliver@onigiri".activationPackage' '.#homeConfigurations."oliver@tempura".activationPackage'`.
- For layout-only changes, compare derivation paths before and after. Configurations that register `self` include the repository's source in the Nix registry, so source-only changes can alter their derivations.
- Darwin hosts that enable Homebrew must set `system.primaryUser`.
- NixOS hosts use integrated Home Manager; their home configurations are activated with the system.
- Keep hardware detection and Disko together in `hardware/<host>.nix`. Use `sudo nixos-generate-config --no-filesystems --show-hardware-config` on the target to refresh detection, preserving the handwritten disk layout.
- Disko manages only ochazuke's NVMe OS disk and its `nixos` root pool (`root`, `nix`, `var`, and `home` datasets). Never add the existing `zfs78` HDD pool to its destructive layout. Its generated script recursively unmounts `/mnt`; finish and verify any migration using that mount tree, then cleanly export the pool before running it.
- On wasabi, Disko only declares and mounts the `nixos` pool; never run its format or destroy modes there. The pool also holds `piu-backup`, the only raw image of the Pump It Up Phoenix SSD, and `piu-work`. The Phoenix SSD itself (`ata-CT240BX500SSD1_2325E6E50108`) must never be written, mounted read-write or given a bootloader. wasabi was installed by recreating `root`, `nix`, `var` and `home` by hand and mounting with `disko --mode mount`.
- Build NixOS on an x86_64 Linux machine with `nix build --no-link --no-write-lock-file .#nixosConfigurations.ochazuke.config.system.build.toplevel`; evaluation alone also works on macOS.
- Keep ad-hoc verification scripts outside the repository; do not commit tests unless requested.
- Rotating an `*-api-key.age` secret needs a manual `systemctl restart <app>-env.service <app>.service` after `nixos-rebuild switch`: the units don't change, so NixOS won't restart them and the old key stays live. For Prowlarr, also update the `apiKey` field on each Sonarr/Radarr indexer (`PUT /api/v3/indexer/<id>?forceSave=true`); its app sync does not re-push a changed key. Filter `magnetUrl`/`downloadUrl` out of Prowlarr search output — they embed the API key. Arr GET responses mask secret fields as `********`; never round-trip a GET body into a PUT without re-setting those fields, and verify by reading the sqlite `Settings` column — the `/test` endpoint resolves masks internally and passes even when the stored value is the mask.
- Manual imports of hand-added batch torrents (`POST /api/v3/command ManualImport`) **move** files even with `downloadId` set: Sonarr/Radarr only hardlink when the torrent is tracked in their own queue. Accept that seeding ends and remove the orphaned torrent, or use `importMode: "copy"` if seeding matters. Sonarr's `manualimport?seriesId=` scans the *library* folder, not `folder=` — omit `seriesId` and let it auto-match.
- Sonarr and Radarr ship with file renaming **off**; it is enabled with TRaSH's anime/movie formats (set through their APIs, not Nix). Raw batch filenames like `Show -77.mkv` make Jellyfin mis-season episodes. `RenameFiles` takes one `seriesId`/`movieId` per command. Replaced files go to `/zfs78/media/recycle/{sonarr,radarr}` for 7 days (same dataset, so moves are free); the directories are created by hand, not by Nix.
- The HDMI monitor on ochazuke runs `modules/nixos/lolesports-kiosk.nix`: cage on tty1 as the `kiosk` user, streamlink → mpv (NVDEC, native Wayland via `MPV_HOME/mpv.conf`) playing whichever LoL Esports match `pick-stream.py` ranks highest. The console is on tty2+. cage hangs on SIGTERM (SIGINT too); `TimeoutStopSec=15` makes stops take 15 s, and a switch that restarts it can leave it `failed` (Restart= does not apply to an explicit stop) — `systemctl start cage-tty1` fixes it. Do not remove its `Conflicts=getty@tty1`: that is what keeps getty/autovt off tty1.
- `modules/nixos/seedbox.nix` pulls finished downloads from the Whatbox slot (`charon.whatbox.ca`, user `oliverni`, shared host in Leesburg VA) with parallel `rclone sync` over SFTP every 3 min into `/zfs78/media/torrents/seedbox/<category>` (home mirrors the slot's `sonarr`/`radarr` folders, deletions included: imports are hardlinks, so a torrent the arr removed from the slot leaves only its library copy); the key is `seedbox-ssh-key.age`, its pubkey is in the slot's `~/.ssh/authorized_keys`. Sonarr/Radarr reach its qBittorrent as the "Seedbox qBittorrent" client at `https://qbittorrent.freedgiraffe.box.ca:443` (the slot's basic-auth proxy, same credentials as SSH) with a remote path mapping `/home/oliverni/files/` → `/zfs78/media/torrents/seedbox/`. It is the only download client: every grab (Nyaa and private trackers alike) lands on the slot and is pulled home; there is no local torrent client. Its WebUI is at https://qbittorrent.freedgiraffe.box.ca (slot credentials). Slot cleanup is the arr-native flow: Prowlarr's per-indexer seed criteria (AvistaZ ratio 1.5 / 14 d, well above its HnR rule of ratio 0.9 or 72 h + 2 h/GB; Nyaa 0.01 / 1 min) reach qBittorrent per torrent, which stops at the goal, and the arrs' Remove Completed then deletes it. Prowlarr treats 0 as unset and would copy another indexer's values, hence 0.01/1. qBittorrent 5.2's `setShareLimits` needs `shareLimitAction=Stop`. qBittorrent on the slot has no seed limits and AutoTMM with `sonarr`/`radarr` category folders under `files/`, and "append `.!qB` to incomplete files" on: the pull is `--size-only` and torrent files have their final size from the first piece, so without the suffix an unfinished file is copied once, zero-filled, and never again (this shipped hollow episodes into the library once; find them with `find -printf '%s %k'`, allocated ≪ size). Moving torrents between seedboxes: export `.torrent`s, add on the new box, **stop the old box first** — AvistaZ allows one client per torrent. Sonarr follows the infohash, but a torrent it loses track of (client migration, a dropped queue item) falls back to filename parsing, and release folders like `[sam] Kusuriya no Hitorigoto S1` then come up "Unknown Series"; import those by mapping episode ids explicitly (`ManualImport` with `seriesId`/`episodeIds` per file, `importMode: copy`). Grabs that stay on one client import on their own regardless of folder name. AvistaZ's API needs Member rank or VIP; register each seedbox IP on your AvistaZ profile (shared/limited for Whatbox). `seedbox-ratio-grab.timer` (same module) builds AvistaZ upload: every 10 min it searches Prowlarr's AvistaZ indexer for freeleech releases under 12 h old and adds them to the slot's qBittorrent in the `ratio` category (never pulled home) and deletes each after 14 days of seeding unless fewer than 3 other seeders remain (the site penalises leaving low-seeded torrents); limits are the unit's environment. It reads `seedbox-qbittorrent-auth.age` (`user:password` for the slot proxy) through `LoadCredential`.
- Admin UIs (`sonarr`, `radarr`, `prowlarr`, `ha`) are at `<name>.ochazuke.org`, tailnet-only: DNS-only A records to `100.68.129.57` plus a `remote_ip` guard in `proxy.nix`; add both when adding one. Home Assistant only honours `use_x_forwarded_for`/`trusted_proxies` from `/var/lib/hass/.storage/http` (its `yaml_migration_done` flag makes it ignore the YAML `http:` block); edit that JSON with HA stopped.
- Photos are shared read-only to guests at `smb://192.168.1.49/photos` on the LAN and `smb://100.68.129.57/photos` over Tailscale. Keep AppleDouble conversion disabled to preserve the archive. Reconnect Mac shares after changing Samba's Apple extensions. Check `smbclient` output for write denial: it can exit successfully even when an SMB command fails.
- jfa-go administration uses `https://admin.accounts.ochazuke.org` over Tailscale (DNS-only A record to `100.68.129.57`). HTTPS and this subdomain preserve its secure login cookie scoped to `accounts.ochazuke.org`. The public `accounts.ochazuke.org` exposes only invitation pages, their assets, and signup/CAPTCHA endpoints; verify public admin routes return 404 when changing its proxy rules.
- jfa-go seeds its mutable `/var/lib/jfa-go/config.ini` from the agenix credential only when absent. Back up its state directory along with Jellyfin; changing the encrypted seed does not update existing runtime settings.
- `ochazuke.org` serves `oliver-ni/jellyfin-client`, consumed as a flake (`packages.default.override { jellyfinUrl; brandMark; }`; its nixpkgs follows ours). The build recipe and `package-lock.hash` live in that repo, so bumping here is just `nix flake lock --update-input jellyfin-client`. `/seerr/*` is proxied to Seerr with the prefix stripped; `/sonarr/api/v3/{system/status,series/N,episode,queue}` (GET only) is proxied to Sonarr with the API key injected from Caddy's env and gated by `forward_auth` against Seerr's session (`uri /api/v1/auth/me?` — the trailing `?` matters, Seerr 400s on unknown query params); `requests.` keeps Seerr's own UI for admin; `jellyfin.` keeps the API for clients and the arrs.
