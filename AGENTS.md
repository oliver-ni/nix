# Repository conventions

- Group system configurations under `hosts/<platform>/`; keep per-user Home Manager configurations under `home/`.
- Keep shared defaults in `modules/<platform>/base.nix`. Import optional modules explicitly from host or home configurations; do not recursively auto-import modules.
- Do not add a profiles layer unless shared machine roles make it necessary.
- Preserve pinned inputs and existing `stateVersion` values during layout refactors.
- Collapse single-child attribute nesting into dotted paths. Keep attribute sets where they group multiple settings.
- Use blank lines between logical sections and sibling blocks; keep closely related scalar settings together.
- Omit settings that merely repeat defaults unless they document an important hardware or safety requirement; check the pinned module defaults before removing them.
- Keep services and integrations minimal; add optional daemons and hardware support only when needed for the current setup.
- The Macs use Determinate Nix. Keep `nix.enable = false`, but manage `/etc/nix/registry.json` through `environment.etc`, using the `nix.registry` declarations. Do not let nix-darwin replace Determinate's daemon or `nix.conf`.

# Verification

- Use the official `nixfmt` formatter via `nix fmt` (`nixfmt-tree` handles the repository). Check formatting with `nix fmt -- --fail-on-change`.
- Evaluate Darwin outputs with `nix eval --raw .#darwinConfigurations.<host>.system.drvPath`.
- Build Home Manager without activation or replacing `result`: `nix build --no-link --no-write-lock-file '.#homeConfigurations."oliver@onigiri".activationPackage' '.#homeConfigurations."oliver@tempura".activationPackage'`.
- For layout-only changes, compare derivation paths before and after. Configurations that register `self` include the repository's source in the Nix registry, so source-only changes can alter their derivations.
- Darwin hosts that enable Homebrew must set `system.primaryUser`.
- NixOS hosts use integrated Home Manager; their home configurations are activated with the system.
- Keep hardware detection and Disko together in `hardware/<host>.nix`. Use `sudo nixos-generate-config --no-filesystems --show-hardware-config` on the target to refresh detection, preserving the handwritten disk layout.
- Disko manages only ochazuke's NVMe OS disk and its `nixos` root pool (`root`, `nix`, `var`, and `home` datasets). Never add the existing `zfs78` HDD pool to its destructive layout. Its generated script recursively unmounts `/mnt`; finish and verify any migration using that mount tree, then cleanly export the pool before running it.
- On wasabi, Disko only declares and mounts the `nixos` pool; never run its format or destroy modes there. The pool also holds `piu-backup`, the only raw image of the Pump It Up Phoenix SSD, and `piu-work`. The Phoenix SSD itself (`ata-CT240BX500SSD1_2325E6E50108`) must never be written, mounted read-write or given a bootloader. wasabi was installed by recreating `root`, `nix`, `var` and `home` by hand and mounting with `disko --mode mount`.
- Build NixOS on an x86_64 Linux machine with `nix build --no-link --no-write-lock-file .#nixosConfigurations.ochazuke.config.system.build.toplevel`; evaluation alone also works on macOS.
- Keep ad-hoc verification scripts outside the repository; do not commit tests unless requested.

# ochazuke services

Operational notes for the media box. Each module's comments say what it does; this records the hand-configured state around it and the pitfalls already hit once.

## Arr API keys and manual imports

- Rotating an `*-api-key.age` secret needs a manual `systemctl restart <app>-env.service <app>.service` after `nixos-rebuild switch`: the units don't change, so NixOS won't restart them and the old key stays live. For Prowlarr, also update the `apiKey` field on each Sonarr/Radarr indexer (`PUT /api/v3/indexer/<id>?forceSave=true`); its app sync does not re-push a changed key.
- Filter `magnetUrl`/`downloadUrl` out of Prowlarr search output — they embed the API key. Arr GET responses mask secret fields as `********`; never round-trip a GET body into a PUT without re-setting those fields, and verify by reading the sqlite `Settings` column — the `/test` endpoint resolves masks internally and passes even when the stored value is the mask.
- Manual imports of hand-added batch torrents (`POST /api/v3/command ManualImport`) **move** files even with `downloadId` set: Sonarr/Radarr only hardlink when the torrent is tracked in their own queue. Accept that seeding ends and remove the orphaned torrent, or use `importMode: "copy"` if seeding matters. Sonarr's `manualimport?seriesId=` scans the *library* folder, not `folder=` — omit `seriesId` and let it auto-match.
- A torrent Sonarr loses track of (client migration, a dropped queue item) falls back to filename parsing, and release folders like `[sam] Kusuriya no Hitorigoto S1` come up "Unknown Series"; import those by mapping episode ids explicitly (`ManualImport` with `seriesId`/`episodeIds` per file, `importMode: copy`). Grabs that stay on one client import on their own regardless of folder name.
- Sonarr and Radarr ship with file renaming **off**; it is enabled with TRaSH's anime/movie formats (set through their APIs, not Nix). Raw batch filenames like `Show -77.mkv` make Jellyfin mis-season episodes. `RenameFiles` takes one `seriesId`/`movieId` per command. Replaced files go to `/zfs78/media/recycle/{sonarr,radarr}` for 7 days (same dataset, so moves are free); the directories are created by hand, not by Nix.

## Seedbox (`modules/nixos/seedbox.nix`)

- The Whatbox slot (`charon.whatbox.ca`, user `oliverni`, shared host in Leesburg VA) is the only download client: every grab, Nyaa and private trackers alike, lands on its qBittorrent and is pulled home; there is no local torrent client. Sonarr/Radarr reach it as the "Seedbox qBittorrent" client at `https://qbittorrent.freedgiraffe.box.ca:443` (the slot's basic-auth proxy, same credentials as SSH, also its WebUI) with a remote path mapping `/home/oliverni/files/` → `/zfs78/media/torrents/seedbox/`. The SSH key is `seedbox-ssh-key.age` (pubkey in the slot's `~/.ssh/authorized_keys`); `seedbox-qbittorrent-auth.age` is `user:password` for the proxy.
- `seedbox-pull` mirrors the slot's `sonarr`/`radarr` folders home every 3 min with `rclone sync`, deletions included: imports are hardlinks, so a torrent removed from the slot leaves only its library copy. It is `--size-only`, and torrent files have their final size from the first piece, so the pull depends on qBittorrent's "append `.!qB` to incomplete files" (asserted by the ratio grab): without the suffix an unfinished file is copied once, zero-filled, and never again (this shipped hollow episodes into the library once; find them with `find -printf '%s %k'`, allocated ≪ size).
- Slot cleanup is owned by `seedbox-ratio-grab`: Prowlarr's per-indexer seed criteria (AvistaZ ratio 1.5 / 14 d, well above its HnR rule of ratio 0.9 or 72 h + 2 h/GB; Nyaa 0.01 / 1 min — Prowlarr treats 0 as unset and would copy another indexer's values) reach qBittorrent per torrent, which stops at the goal; the grab then deletes the torrent once the arr has imported it (history has a `downloadFolderImported` event and it has left the queue) and every file is at home at full size. qBittorrent 5.2's `setShareLimits` needs `shareLimitAction=Stop`.
- The arrs' own Remove Completed is **off** on both clients and must stay off: Sonarr/Radarr only hardlink while the torrent is still seeding; a torrent already stopped at its goal (every Nyaa grab, before the pull starts) they import by *moving* and then delete the download folder, taking the pull's in-flight `.partial` files with it, so the next pull re-copies them (Food Wars S01–S04 churned ~2× their size this way).
- Hand-added torrents the arrs never grabbed have no history, so the cleanup leaves them; remove those by hand after their manual import. qBittorrent on the slot has no seed limits of its own and AutoTMM with `sonarr`/`radarr` category folders under `files/`.
- Moving torrents between seedboxes: export `.torrent`s, add on the new box, **stop the old box first** — AvistaZ allows one client per torrent.
- `seedbox-ratio-grab.timer` builds upload on AvistaZ and AnimeZ (same network, same rules; Prowlarr indexers 2 and 3, both `AvistazSettings` with username/password/PID; the API needs Member rank or VIP, and each seedbox IP must be registered on each site's profile — shared/limited for Whatbox). Every 10 min it searches each tracker's indexer for freeleech releases under 2 h old whose swarm still has leechers and adds them in that tracker's category (`ratio-avistaz`, `ratio-animez`; never pulled home), and deletes each at ratio 0.9 or 14 days of seeding unless fewer than 3 other seeders remain (the sites penalise leaving low-seeded torrents), or when still under 10% after an idle hour. The limits are the unit's environment.
- Both sites rate-limit: auth 429s (`/api/v1/jackett/auth`) when Prowlarr tests and saves an indexer back to back, and the search API allows ~10 requests/min — the rate Prowlarr's hardcoded 6 s spacing for AvistaZ-family indexers produces, so a Sonarr season search (4 queries per anime episode: two title aliases × `Title 05`/`S01E05`) hits 429 within two minutes and Prowlarr disables the indexer for an hour. AnimeZ therefore has a Prowlarr query limit of 9/hour (set through its indexer form, not Nix): past it Prowlarr returns empty results without touching the site. Steady traffic is ~12/hour (ratio-grab 6, Sonarr RSS 4, Radarr RSS 2), so AnimeZ RSS is skipped for part of each hour and a season search there is effectively Nyaa-only.
- Nyaa's search returns one page of 75 rows sorted newest-first, which hides old batches (2011 fansubs for a title with many single-episode posts); Prowlarr indexer 4 `Nyaa.si (by seeders)` is a copy of indexer 1 with `sort: seeders` on the `Search only (no RSS)` app profile, so Sonarr/Radarr searches hit both pages while RSS stays newest-first.

## Manga (`modules/nixos/manga.nix`)

- Suwayomi (`suwayomi.ochazuke.org`, tailnet-only, no login; Keiyoushi extension store) fetches chapters as CBZ into `/zfs78/media/manga/mangas/<source>/<title>/`; Komga (`manga.ochazuke.org`, public) serves that tree as its library. Libraries, users and scan intervals are Komga state set in its UI, not Nix. Readers point at Komga: web, Mihon/Paperback/Aidoku Komga sources, OPDS at `/opds/v2/catalog`.
- Suwayomi's package is pinned to the current stable jar (nixpkgs' 2.1 can't read Keiyoushi's protobuf store or v1.6 extensions — drop the override once nixpkgs ships ≥ 2.3). Nix regenerates its `server.conf` on every start, so anything under Settings → Server in its UI that is also set in the module reverts; change those in Nix.

## Identity (`modules/nixos/kanidm.nix`)

- Kanidm is at `https://accounts.ochazuke.org` (public login UI; admin only through the `kanidm` CLI on the box as `idm_admin`, password in `kanidm-idm-admin-password.age`). It terminates its own TLS on loopback (`:8443`, self-signed cert from `kanidm-tls.service` under `/var/lib/kanidm/tls`); Caddy proxies to it with `tls_insecure_skip_verify`.
- Groups (`ochazuke_users`, `ochazuke_admins`) and the OAuth2 clients (`jellyfin`, `komga`) are provisioned from Nix with `overwriteMembers = false`, so memberships added by hand survive rebuilds. Provisioning only adds and updates: a scope map dropped from Nix stays live until `kanidm system oauth2 delete-scope-map <client> <group>`. Komga's is on `ochazuke_admins` only until the client's Manga tab lands, which hides it from everyone else's app list.
- Persons are not in Nix: `ochazuke-invite <name> [display name] [email]` creates one, adds `ochazuke_users` and prints a 24 h reset link where they set a password/passkey. Komga matches and auto-creates users by email, so set the real address up front (the default is `<name>@ochazuke.org`); changing it after someone's first Komga login makes Komga create a second user unless the Komga user is edited too.
- The package is `kanidm_1_x.withSecretProvisioning` (required for `adminPasswordFile`/`basicSecretFile`); when nixpkgs marks the pinned minor EOL the build refuses it — run `kanidmd domain upgrade-check` and move to the next minor rather than adding a `permittedInsecurePackages` entry.
- Jellyfin signs in through the SSO-Auth plugin (installed from its plugin repository in Jellyfin, not Nix; provider `ochazuke` set via `POST /sso/OID/Add/ochazuke`, entry point `https://jellyfin.ochazuke.org/sso/OID/start/ochazuke`, `SchemeOverride = https` because Caddy speaks http to it). It matches Jellyfin users by Kanidm username and creates missing ones; admin comes from the `jellyfin_roles` claim (`ochazuke_admins` → `admin`). SSO'd users have their Jellyfin `AuthenticationProviderId` pointed at the plugin's non-existent provider, which makes Jellyfin refuse password logins for them; native apps sign in with Quick Connect approved from the client. `tv` keeps its password.
- Komga's OIDC client is in `manga.nix` (public PKCE client, issuer `…/oauth2/openid/komga`).
- jfa-go (`jfa-go.nix`) is kept only as the rollback path while Kanidm beds in: its admin UI is still at `https://admin.accounts.ochazuke.org` over Tailscale, but the public `accounts.ochazuke.org` now serves Kanidm, so its invitation pages are unreachable. Its mutable state is `/var/lib/private/jfa-go` (DynamicUser; `/var/lib/jfa-go` is the alias), backed up to `/var/backup/jfa-go-<date>.tar.gz` before the cutover. Remove the module, its secret and the admin route once Kanidm logins are confirmed.

## Client and proxy (`modules/nixos/jellyfin-client.nix`, `modules/nixos/proxy.nix`)

- `ochazuke.org` serves `oliver-ni/jellyfin-client`, consumed as a flake (`packages.default.override { jellyfinUrl; ssoProvider; brandMark; }`; its nixpkgs follows ours). The build recipe and `package-lock.hash` live in that repo, so bumping here is just `nix flake lock --update-input jellyfin-client`.
- `/sso/*` is proxied to Jellyfin with the Host kept so the SSO plugin's redirect lands on `ochazuke.org` (registered in Kanidm) and the client, not jellyfin-web, receives the token. Seerr's session comes from Jellyfin Quick Connect (enabled in Jellyfin's settings, not Nix). `/seerr/*` is proxied to Seerr with the prefix stripped. `/sonarr/api/v3/{system/status,series/N,episode,queue}` (GET only) is proxied to Sonarr with the API key injected from Caddy's env and gated by `forward_auth` against Seerr's session (`uri /api/v1/auth/me?` — the trailing `?` matters, Seerr 400s on unknown query params). `requests.` keeps Seerr's own UI for admin; `jellyfin.` keeps the API for native clients and the arrs.
- Admin UIs (`sonarr`, `radarr`, `prowlarr`, `suwayomi`, `ha`) are at `<name>.ochazuke.org`, tailnet-only: DNS-only A records to `100.68.129.57` plus the `tailnetOnly` map in `proxy.nix`; add both when adding one. Public apps need no DNS record (wildcard CNAME → apex), only a host handle.
- Home Assistant only honours `use_x_forwarded_for`/`trusted_proxies` from `/var/lib/hass/.storage/http` (its `yaml_migration_done` flag makes it ignore the YAML `http:` block); edit that JSON with HA stopped.

## Kiosk (`modules/nixos/lolesports-kiosk.nix`)

- The HDMI monitor runs cage on tty1 as the `kiosk` user, streamlink → mpv (NVDEC, native Wayland via `MPV_HOME/mpv.conf`) playing whichever LoL Esports match `pick-stream.py` ranks highest. The console is on tty2+.
- cage hangs on SIGTERM (SIGINT too); `TimeoutStopSec=15` makes stops take 15 s, and a stop can leave it `failed` (Restart= does not apply to an explicit stop) — `systemctl start cage-tty1` fixes it.
- Keep `systemd.targets.getty.wants = mkForce [ ]`: the getty module otherwise makes getty.target want `autovt@tty1` (the same unit as `getty@tty1`; a `/dev/null` mask of `getty@tty1` does not catch the alias), every `switch-to-configuration` starts it, and cage's `Conflicts=` then stops cage. Keep `linger = true` on the kiosk user: as a system user it gets a `user-light` session with no `user@` manager, and switch-to-configuration then fails its per-user activation (exit 4) for as long as cage is logged in.
